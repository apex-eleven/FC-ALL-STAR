# ชุดขึ้นออนไลน์ GitHub + Vercel (+ เตรียม Firebase) — 8 ไฟล์

ลากทั้งโฟลเดอร์ทับโปรเจกต์ · **อ่านขั้นตอนเต็มที่ `docs/DEPLOY.md`**

```
vercel.json                        ตั้งค่า Vercel (เจอเองอัตโนมัติ ไม่ต้องกรอกอะไร)
.env.example                       รายการ env ของ Firebase
.gitignore                         + กันไฟล์สำรองที่มีข้อมูลไอดีขึ้น git
firestore.rules                    กฎความปลอดภัย Firestore พร้อมวาง
package.json                       + คำสั่ง media:compress
scripts/compress-media.mjs         บีบรูป/วิดีโอ + แก้ชื่อไฟล์ที่อ้างถึง
src/features/cloud/firebase.ts     ตัวอ่าน env · ไม่มีค่า = ปิดโหมดคลาวด์ ไม่พัง
docs/DEPLOY.md                     คู่มือเต็ม
```

## สรุปสั้น

**ขั้นที่ 1 — ทำได้เลยวันนี้ คนอื่นเข้าเล่นได้จริง**

```
1. node scripts/compress-media.mjs --apply     232 MB -> ~60 MB
2. เปิดเกมเช็ครูปการ์ดว่ายังขึ้นครบ
3. git push ขึ้น GitHub
4. Vercel -> Add New Project -> เลือก repo -> Deploy
```

ได้ URL แล้วส่งให้ใครก็เล่นได้ · ทุกคนได้คลังการ์ด แพ็ค ลีก ตามที่คุณตั้งไว้

**ข้อจำกัดของขั้นที่ 1 ที่ต้องรู้ก่อน:** เซฟอยู่ในเบราว์เซอร์ของแต่ละคน
ย้ายเครื่องแล้วไม่ตามไป · แผงแอดมินบนเว็บที่ deploy แล้วแก้ได้แค่ในเบราว์เซอร์ตัวเอง
→ แก้ที่เครื่องคุณแล้ว push ให้ deploy ใหม่ คือวิธีที่ถูกต้องของขั้นนี้

**ขั้นที่ 2 — Firebase (บัญชีบนคลาวด์) ยังไม่ได้ทำให้**

เตรียมพื้นไว้ให้แล้ว (ตัวอ่าน env + กฎ Firestore + ขั้นตอนตั้งค่าใน Console)
แต่ตัวระบบล็อกอินยังต้องเขียนเพิ่มราว 400–600 บรรทัด

เหตุผลที่แยกไว้ ไม่ใช่ความขี้เกียจ: ตอนนี้เกมแฮชรหัสผ่านเองในเบราว์เซอร์
ถ้าเอาโครงเดิมยกไปวางบน Firestore ตรง ๆ = ทุกคนโหลดแฮชรหัสผ่านของคนอื่นได้
ต้องเปลี่ยนให้ Firebase Auth เป็นคนตรวจรหัสแทน ซึ่งแตะหัวใจของระบบล็อกอิน
และต้องทดสอบกับโปรเจกต์ Firebase จริงก่อนถึงจะกล้าส่ง

รายละเอียดงานที่เหลืออยู่ในตารางท้าย `docs/DEPLOY.md` — บอกมาได้เลยถ้าจะให้ทำต่อ
