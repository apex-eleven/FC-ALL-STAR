# ขั้นที่ 1 — ขึ้น GitHub + Vercel (พร้อมใช้แล้ว)

## 1.1 บีบไฟล์สื่อก่อน (สำคัญ)

ตอนนี้โปรเจกต์หนัก **232 MB** โดย 225 MB คือรูปการ์ดกับวิดีโอ ขึ้น git ได้แต่จะช้ามาก
และ clone ทีนึงกินเวลานาน

```bash
npm run media:compress            # ดูก่อนว่าจะเปลี่ยนอะไร ไม่แตะไฟล์
node scripts/compress-media.mjs --apply
```

ผลที่วัดจริงจากไฟล์ของคุณ:

| ของ | ก่อน | หลัง |
|---|---|---|
| รูปการ์ด 80 ไฟล์ (gif -> webp) | 126 MB | ~47 MB |
| walkout-stage.mp4 | 77 MB | ~7 MB |
| walkout-flight.mp4 | 22 MB | ~3 MB |
| **รวม** | **232 MB** | **~60 MB** |

สคริปต์**แก้ชื่อไฟล์ที่อ้างถึงใน `catalogue.json` และ `admin.json` ให้ด้วย** —
ข้อนี้คือข้อที่ลืมแล้วพังเงียบ ๆ เพราะคลังการ์ดเก็บชื่อไฟล์ไว้ ถ้าแปลง `.gif` เป็น
`.webp` แล้วไม่แก้ที่อ้าง การ์ดจะรูปหายหมดโดยไม่มี error ขึ้นเลยสักบรรทัด

> ต้องมี `ffmpeg` ในเครื่องก่อน · Windows โหลดจาก https://ffmpeg.org/download.html
> แล้วเพิ่มลง PATH

**เปิดเกมเช็ครูปการ์ดก่อนคอมมิต**

## 1.2 ขึ้น GitHub

```bash
git init
git add .
git commit -m "FC ALL-STAR"
git branch -M main
git remote add origin https://github.com/<ชื่อคุณ>/<ชื่อ repo>.git
git push -u origin main
```

ต้องมีไฟล์พวกนี้ขึ้นไปด้วย ไม่งั้นคนอื่นเปิดมาจะไม่มีการ์ดเลย:

```
public/config/admin.json        ตั้งค่าเกมทั้งหมด
public/players/catalogue.json   คลังการ์ด
public/players/manifest.json    รายชื่อไฟล์รูป
public/players/*.webp           รูปการ์ด
public/brand/*                  ไอคอนกับพื้นหลัง
```

`.gitignore` กันไว้แล้วสองอย่าง: `node_modules` และ `fc-allstar-backup-*.json`
(ไฟล์สำรองที่มีข้อมูลไอดีผู้เล่น — **ห้ามขึ้น git**)

## 1.3 ต่อ Vercel

1. https://vercel.com -> Add New -> Project -> เลือก repo
2. Framework จะถูกตรวจเป็น **Vite** อัตโนมัติ · ไม่ต้องแก้อะไร
   (`vercel.json` ในโปรเจกต์ตั้งค่าไว้ให้หมดแล้ว)
3. Deploy

ได้ URL มาแล้วส่งให้ใครก็เล่นได้ทันที · push ขึ้น main ครั้งต่อไป Vercel deploy ให้เอง

## 1.4 ขั้นที่ 1 ได้อะไร / ยังไม่ได้อะไร

**ได้**
- คนอื่นเข้าเล่นได้จริงผ่าน URL
- ทุกคนได้คลังการ์ด แพ็ค ดราฟต์ ลีก แบนเนอร์ ตามที่คุณตั้งไว้
- สมัครไอดีในเว็บได้ เล่นได้ครบทุกระบบ

**ยังไม่ได้**
- **เซฟอยู่ในเบราว์เซอร์ของแต่ละคน** ย้ายเครื่องแล้วเซฟไม่ตามไป
- ไม่มีตารางคะแนนรวมระหว่างผู้เล่นจริง (ลีกยังเป็นการจำลองกับ AI)
- แผงแอดมินบนเว็บที่ deploy แล้วแก้ได้แค่ในเบราว์เซอร์ตัวเอง ไม่กระทบคนอื่น
  → **แก้ตั้งค่าที่เครื่องคุณ แล้ว `git push` ให้ Vercel deploy ใหม่** คือวิธีที่ถูกต้อง
  ของขั้นนี้

# ขั้นที่ 2 — Firebase (บัญชีบนคลาวด์)

ขั้นนี้ทำให้ **ไอดีเดียวเล่นได้ทุกเครื่อง** และแอดมินแก้ตั้งค่าแล้วทุกคนเห็นทันที
โดยไม่ต้อง deploy ใหม่

## 2.1 สิ่งที่เตรียมมาให้แล้วในโปรเจกต์

```
src/features/cloud/firebase.ts   อ่าน env · ไม่มีค่า = ปิดโหมดคลาวด์ ไม่พัง
firestore.rules                  กฎความปลอดภัย พร้อมวางใน Console
.env.example                     รายการ env ที่ต้องกรอก
```

## 2.2 ขั้นตอนฝั่ง Firebase

1. สร้างโปรเจกต์ที่ https://console.firebase.google.com
2. **Authentication** -> Sign-in method -> เปิด **Email/Password**
3. **Firestore Database** -> Create database -> production mode
4. แท็บ **Rules** -> ก๊อปทั้งไฟล์ `firestore.rules` ไปวาง -> Publish
5. Project settings -> Your apps -> Web -> ก๊อปค่า config 6 ตัว
6. Vercel -> Project -> Settings -> Environment Variables -> ใส่ทั้ง 6 ตัว
   (ชื่อตรงตาม `.env.example`) แล้ว redeploy
7. ตั้งตัวเองเป็นแอดมิน: Firestore -> สร้าง collection `admins` -> document id =
   **uid ของคุณ** (ดูได้ที่แท็บ Authentication) เนื้อใน document ว่างเปล่าก็ได้

## 2.3 สิ่งที่ยังต้องเขียนโค้ดเพิ่ม

**ยังไม่ได้ทำให้** และทำไม่ได้แบบวางแล้วใช้เลย เพราะต้องแก้ระบบล็อกอินที่มีอยู่:

| งาน | ทำไมต้องแก้ |
|---|---|
| สมัคร/ล็อกอินผ่าน Firebase Auth | ตอนนี้เกมแฮชรหัสผ่านเองแล้วเก็บในเบราว์เซอร์ · ถ้าย้ายไปเก็บบน Firestore ตรง ๆ แปลว่าทุกคนโหลดแฮชรหัสผ่านคนอื่นได้ ต้องให้ Firebase Auth เป็นคนตรวจรหัสแทน |
| เซฟลง `accounts/{uid}` | เพื่อให้เซฟตามตัวคนเล่นไปทุกเครื่อง |
| จองชื่อใน `usernames/{ชื่อ}` | Firebase Auth ใช้อีเมล เกมนี้ใช้ชื่อผู้ใช้ ต้องมีตารางแปลงชื่อ -> uid |
| อ่าน/เขียนตั้งค่าที่ `config/admin` | แอดมินแก้แล้วทุกคนเห็นทันที ไม่ต้อง deploy ใหม่ |

`firebase.ts` เตรียม `usernameToEmail()` ไว้ให้แล้ว (แปลง `ddx` เป็น
`ddx@players.fcallstar.local`) เพื่อให้หน้าล็อกอินยังใช้ชื่อผู้ใช้เหมือนเดิม
และเติมอีเมลจริงทีหลังได้

**ประเมินงาน:** แก้ `AuthContext` + เขียน backend ใหม่ราว 400–600 บรรทัด
ต้องทดสอบกับโปรเจกต์ Firebase จริง — บอกมาได้เลยถ้าจะให้ทำต่อ

> ค่า `VITE_FIREBASE_*` ไม่ใช่ความลับ Firebase ออกแบบให้ฝังในเว็บได้
> ความปลอดภัยจริงอยู่ที่ `firestore.rules` ไม่ใช่ที่การซ่อนคีย์
